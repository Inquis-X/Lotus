# Демонстрация земельной функции

Сценарий показывает действующий путь «документ → кандидаты → проверка → правила → реестр → проект отчёта → новая редакция». Материалы синтетические, сроки и условия вымышлены. Проверяется работа программы; юридическая обоснованность и качество анализа реальных регламентов этим примером не подтверждаются.

## Подготовка

Из корня репозитория выполните в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts/generate_function_demo.py
$env:LOTUS_DATA_DIR = Join-Path (Get-Location) 'tmp\land-demo-session'
.\.venv\Scripts\python.exe desktop.py
```

Генератор создаёт три входных DOCX и `manifest.json` в `data/gold/functions`, не меняя базу данных. Повторная генерация даёт те же байты. Если файл изменён пользователем, команда остановится; другую папку можно задать через `--output путь`.

Если каталог данных уже использовался, сведения сохранятся. Для показа с нуля выберите другое имя папки. Исходные документы после загрузки не перемещайте и не изменяйте: приложение проверяет контрольные суммы. Команда `python scripts/reset_demo.py` очищает базу выбранного каталога и восстанавливает демонстрационные документы.

## Исходная редакция

1. Откройте «Анализ функций», подтвердите отсутствие персональных данных и выберите `data/gold/functions/land_v1.docx`.
2. Укажите `Учебная редакция 1`. Нажмите «Найти записи в DOCX». Ожидаются 9 записей: функция, процедура, 5 этапов, роль и контроль.
3. Сохраните кандидатов. Подтвердите каждую запись отдельно, проверяя цитату и связь и вводя обоснование. Порядок: функция, процедура, этапы, роль и контроль. Без подтверждения ядро не допускает запуск правил.
4. Выберите строку процедуры и нажмите «Проверить формулировки выбранной процедуры». Ожидаются 5 проверенных этапов и 2 новых кандидата на этапе подготовки проекта решения.
5. В «Реестре рисков» выберите происхождение «Найдено автоматически». Покажите цитату, координату, редакцию и правило. После проверки контекста подтвердите учебные оценки с собственным обоснованием. Повторный запуск правил не создаёт дубликаты.
6. На «Карте муниципалитета» покажите функцию и этапы. Функция находится в группе «Подразделение по земельным отношениям». Для ранее загруженной функции выберите её на карте и нажмите «Указать подразделение». Цвет отражает статус проверки.
7. В «Отчётах» выберите две подтверждённые записи, сформируйте предпросмотр и сохраните проект карты рисков. Ожидаются две записи, происхождение, правила, цитаты и ссылки на источники. Печатную вёрстку дополнительно проверьте в редакторе документов; тесты проверяют содержание.

## Смена редакции (отрицательный контроль)

1. Загрузите `land_v2.docx` в «Анализе функций» и укажите `Учебная редакция 2`. Список проверки покажет только записи этого документа; записи прежней редакции сохраняются в базе.
2. Извлеките и подтвердите все записи с обоснованием.
3. Выберите процедуру и нажмите «Проверить формулировки выбранной процедуры»: ожидается 0 совпадений и сообщение «Рисков не найдено». Кнопка проверки блокируется, кнопка-сигнал остаётся неактивной. Это означает только отсутствие искомых формулировок в текущих цитатах.
4. Вернитесь к записям первой редакции: кнопка-сигнал показывает необработанные находки и ведёт в реестр. Отклоните прежние находки с обоснованием о смене основания, если редакция заменила их. История сохраняется. Ранее сохранённый DOCX остаётся историческим срезом и автоматически не переписывается.

## Контрольный пример

В отдельном каталоге данных загрузите `land_control.docx`, редакция `Контрольный пример 1`. После извлечения и подтверждения ожидаются те же 9 записей и 5 этапов, но 0 находок. Это отрицательный тест двух правил, а не заключение о полном отсутствии рисков.

Для показа правил по отдельности используйте `land_v3.docx` (только «в разумный срок», F02) и `land_v4.docx` (только «при необходимости», F04): каждый даёт ровно одну находку в реестре.

## Автоматическая проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_function_demo.py
```

Проверяются воспроизводимость файлов, защита изменённых источников, полный цикл с пересмотром, контрольные примеры и загрузка через нативный интерфейс. Ожидания и SHA-256 файлов содержатся в `manifest.json`. Подтверждения в тестах имитируют действия специалиста только в изолированной базе; генератор не создаёт решений от его имени.
