# Лотос

**Документально обоснованная оценка коррупционных рисков муниципальных функций.** Рабочее место специалиста подразделения по профилактике коррупционных и иных правонарушений. Все демонстрационные документы и данные синтетические.

## Возможности

Приложение реализует сценарий концепции 2.0: специалист загружает размеченный DOCX, проверяет извлечённые сведения, запускает поиск двух демонстрационных формулировок, оценивает находки и формирует проект карты рисков. При смене редакции основания проверяются повторно.

В основной навигации доступны:

1. **Главная** — сводка сохранённых функций и находок.
2. **Карта муниципалитета** — иерархия «подразделение → функция → процедура → этап → роли и контроли»; цвет показывает статус проверки.
3. **Документальный центр** — локальный предпросмотр DOCX, XLSX, CSV и PDF с координатами и реквизитами источника.
4. **Анализ функций** — пошаговая загрузка, извлечение кандидатов, решения специалиста, проверка формулировок. Список проверки показывает записи выбранного документа; кнопка сброса удаляет его записи вместе с решениями. При нулевом результате проверки формулировок кнопка блокируется с сообщением «Рисков не найдено», при находках программа предлагает перейти в реестр рисков. Кнопка-сигнал рядом с кнопкой проверки показывает число необработанных находок по записям документа и ведёт в реестр.
5. **Реестр рисков** — ручные и автоматические находки с основаниями, ограничениями, мерами и обоснованиями решений.
6. **База практики** — синтетические учебные примеры и обоснованные связи с записями реестра; это не судебные акты.
7. **Отчёты** — проект карты коррупционных рисков DOCX со ссылками `[ИN]` на источники.

[Алгоритм проверки по Методике № 96](docs/analysis_method.md) доступен также на четвёртом шаге анализа функций.

[Пошаговая демонстрация земельной функции](docs/ДЕМОНСТРАЦИЯ_ЗЕМЕЛЬНОЙ_ФУНКЦИИ.md) использует комплект `data/gold/functions`: `land_v1.docx` (обе формулировки), `land_v3.docx` (только оценочный срок), `land_v4.docx` (только условие действия), а также «чистые» `land_v2.docx` и `land_control.docx` без совпадений.

## Принципы

- Оцениваются функции, условия и документальные основания, а не личность.
- Каждый кандидат и каждая находка требуют решения специалиста с обоснованием.
- Вывод связывается с правилом, цитатой, координатой, редакцией и ограничениями.
- Правила и шаблоны находятся в `config/*.yaml`; они демонстрационные и требуют калибровки.
- Действия сохраняются в журнале. Внешние сервисы и сетевые загрузки не используются.

## Запуск

Для запуска Windows-сборки распакуйте архив целиком, откройте `Lotus.exe` и следуйте `START_WINDOWS.txt`. Учебные DOCX находятся рядом с программой в `data/gold/functions`; после загрузки не перемещайте и не изменяйте их, чтобы контрольные суммы оставались проверяемыми.

Для запуска из исходников нужен Python 3.11 или новее:

```bash
python -m pip install -r requirements.txt
python desktop.py
```

Приложение использует нативные виджеты PySide6. HTTP-сервер, браузер, WebView, сетевые порты и дочерние процессы не нужны. Бизнес-логика выполняется в одном процессе.

Данные пользователя по умолчанию находятся в подпапке `user_data` рядом с программой (при запуске из исходников — в корне проекта, в сборке — рядом с `Lotus.exe`). Каталог можно изменить через `LOTUS_DATA_DIR`, путь к SQLite — через `LOTUS_DB_PATH`.

Сброс базы анализа функций и восстановление демонстрационного комплекта:

```bash
python scripts/reset_demo.py
```

Проверка запуска без интерактивного сеанса:

```bash
python desktop.py --check
```

### Сборка Windows-дистрибутива

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build_desktop.ps1 -OutputDirectory dist
```

Результат — `dist/Lotus.exe`, учебные документы и `START_WINDOWS.txt` в `dist`, а также архив `dist.zip`. Самопроверка сборки включена в скрипт. Повторная проверка:

```powershell
$env:LOTUS_DATA_DIR = Join-Path (Get-Location) 'tmp\exe-check'
.\dist\Lotus.exe --check
```

EXE не подписан; Windows SmartScreen может показать предупреждение. Однофайловая сборка распаковывает ресурсы во временный каталог при запуске.

## Проверки

```bash
python -m pytest -q
python desktop.py --check
```

Тесты проверяют разбор документов, извлечение по шаблонам, решения специалиста, правила F02/F04, смену редакций, источники, отчёты, учебную практику, терминологию и запуск окна. Воспроизводимый демонстрационный сценарий находится в `tests/test_function_demo.py`.

## Границы MVP

Это учебная система поддержки специалиста. Реальные персональные данные, авторизация и автоматическое принятие решений не входят в продукт. OCR для сканов не выполняется. Автоматического сравнения редакций нет: изменения сопоставляет и подтверждает специалист.

Два правила ищут «в разумный срок» и «при необходимости» в подтверждённых цитатах этапов; учитываются словоформы и перестановка слов (наборы форм и ширина окна — в `config/rules.yaml`). Ноль совпадений не означает отсутствия рисков. Результаты на небольшом синтетическом комплекте не переносятся на реальные документы без отдельной методической и юридической проверки. Печатную вёрстку созданного DOCX следует проверить в редакторе документов.

## Структура

- `desktop.py` — точка входа нативного приложения.
- `lotus/functions/` — модель, сервис, извлечение, правила, практика и отчёты концепции 2.0.
- `lotus/documents.py`, `sources.py`, `privacy.py`, `audit.py`, `db.py`, `report.py` — инфраструктура документов, источников, журнала, SQLite и DOCX.
- `lotus/ui/` — семь разделов и журнал действий.
- `config/` — правила и шаблоны; `data/` — синтетические учебные материалы.
- `scripts/` — генерация и сброс демо, сборка и проверка Windows-релиза.
- `docs/` — действующие инструкции и архив прежней концепции.
- `AGENTS.md` — правила проекта; `CHANGELOG.md` — история изменений.

Архитектурные записи прежней версии сохранены только для истории в `docs/LOTUS_AGENT_PLAN_АРХИВ.md` и не описывают действующее приложение.
